# Contributing

## Layout

```
src/
  core/        what every Reeds API shares: the client (credentials, token, HTTP, retries,
               idempotency keys), errors, pagination, files, webhook signatures
  apis/
    shipping/  the Shipping API module: types, events, and the resource classes
  generated/   types generated from spec/ (never edit by hand)
  client.ts    the Reeds class: one client, a property per API module
spec/          copies of the APIs' OpenAPI specs, taken from sendx-api by the sync-spec workflow
test/          unit tests (vitest), test/e2e (the real API in Test mode), test/smoke.mjs (the build on Node 18+)
```

The method names match the Reeds PHP and Python libraries, so code reads the same in each language.

## Checks

```sh
npm ci
npm run typecheck
npm test
npm run build && node test/smoke.mjs
```

Development needs Node 22 or later; the published package supports Node 18 and later (CI runs the smoke test on 18, 20, 22 and 24).

## A spec change

The sync-spec workflow opens a pull request when sendx-api deploys a changed spec to production. `npm run generate` rebuilds `src/generated/`. `test/coverage.test.ts` fails until every operation in the spec has a method and every webhook event type is in the module's event list. Add the method, a test, a CHANGELOG entry, then merge.

## Adding a Reeds API

1. The API follows the shared rules (path `/<api>/v<n>`, OAuth scope, envelopes, cursor pagination, Idempotency-Key, `Retry-After`, `X-Request-Id`, one webhook format). Its spec is in sendx-api's `openapi/`.
2. Add it to `APIS` in `scripts/generate.mjs` and to the sync-spec workflow; put its spec in `spec/` and run `npm run generate`.
3. Add `src/apis/<api>/` (types, events, resources), a property on `Reeds` in `src/client.ts`, its events to `ReedsEvent`, a subpath entry (`src/<api>.ts`, tsup and package.json `exports`), and its operation map in `test/coverage.test.ts`.
4. Add its end-to-end scenario to `test/e2e/`.
5. Release as a minor version.

## Webhook test vectors

`test/fixtures/webhook-vectors.json` is generated by sendx-api's own signing code (`src/modules/developers/webhooks/signature.ts`), so the library and the server can't drift. Every Reeds library runs the same file. Don't edit it by hand: regenerate it from sendx-api.

## Releasing

1. Update `version` in package.json and `src/version.ts`, and the CHANGELOG.
2. Merge to main, then push the tag `vX.Y.Z`. The release workflow builds, tests and stages the version on npm, with provenance.
3. An owner of the npm package publishes the staged version with their 2FA: `npm stage list reeds-sdk`, then `npm stage approve <stage-id>` (or on npmjs.com).
